# Contributing to DevNa

Thanks for helping improve DevNa.

## Before making changes

1. Open an issue or write down the problem and intended outcome.
2. Keep changes focused and easy to review.
3. Never include API keys, access tokens, passwords, private user data, or confidential plugin release artifacts.
4. Document new configuration and provide safe defaults.

## Pull requests

- Explain the motivation and the behavior changed.
- Include tests or clear manual verification steps.
- Call out security, permissions, and compatibility implications.
- Do not claim a feature works until it has been tested.

## Scope and identity

This repository is the project's source of truth for code and documentation. The existing ChatGPT plugin identity is managed separately. Changes to plugin IDs, release ownership, or discoverability must be deliberate and must not be inferred from this repository's name or version.
